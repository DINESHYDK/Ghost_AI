# Feature 04: Editor Home, Project Dialogs and Sidebar Actions

## Goal

Build the `/editor` home screen, the Create / Rename / Delete project dialogs, and per-project actions in the sidebar. Everything runs on in-memory mock data. No API calls, no database, no persistence.

## Dependencies

Features 01, 02 and 03 are done. Reuse, and do not rebuild:

- `components/editor/editor-dialog.tsx` (controlled dialog shell: `open`, `onOpenChange`, `title`, `description?`, `children?`, `footer?`)
- `components/editor/editor-shell.tsx` (client component that owns `isSidebarOpen`)
- `components/editor/project-sidebar.tsx` (props `isOpen`, `onClose`)
- `components/editor/editor-navbar.tsx` (do not modify)
- shadcn `Button`, `Input`, `Dialog`, `Tabs`, `ScrollArea`

## Scope

In scope:

1. `components/editor/editor-home.tsx`: the centered home content.
2. `components/editor/project-dialogs.tsx`: the Create, Rename and Delete dialogs.
3. `hooks/use-project-dialogs.ts`: the dedicated hook for dialog, form and loading state.
4. `lib/mock-projects.ts` and `types/project.ts`: mock data and its interface.
5. Changes to `project-sidebar.tsx` and `editor-shell.tsx` listed below.
6. One new design token, `--scrim`, in `globals.css` (see "Mobile scrim").
7. Updating `context/ui-context.md`, `context/code-standards.md` and `context/progress-tracker.md`.

Out of scope (do not start these):

- Any API call, server action, route handler, database or Prisma use, `localStorage`, or other persistence. Reloading the page resets everything.
- Opening a project. Project rows in the sidebar are not clickable in this unit.
- The collaborator, invite or share UI. The sidebar `Shared` tab only lists shared projects.
- Changes to `editor-navbar.tsx`, `editor-dialog.tsx`, `app/editor/page.tsx`, `proxy.ts`, auth, `components/ui/*`, and every token except the one new `--scrim`.
- The lime accent button. All buttons here use shadcn's existing variants (see "Open question" in `progress-tracker.md`).
- Any slug, URL or room-ID concept. A project's ID is generated by the database (a cuid) in later specs and is also the Liveblocks room ID. Nothing in this unit derives an ID or a URL from the project name.

## Mock data

- `types/project.ts`: `export interface ProjectListItem { id: string; name: string; isOwner: boolean }`.
- `lib/mock-projects.ts`: exports an initial list of 6 items: 4 owned (one with a very long name, to test truncation) and 2 shared. Suggested names: "Ride-sharing backend", "E-commerce checkout", "Chat service", "Real-time collaborative document editing platform" (owned), and "Payments platform", "Notification system" (shared).
- `EditorShell` keeps the list in `useState`, initialised from the mock. Create adds an item (`isOwner: true`, a generated local id), Rename updates the name, Delete removes the item. All changes are in memory only.
- This mock is temporary. A later unit replaces it with real data. Keep the interface minimal so it is easy to swap, and mark `lib/mock-projects.ts` in a one-line comment as temporary.

## Editor home: `components/editor/editor-home.tsx`

- Rendered inside the existing `<main className="... bg-page">` of `EditorShell`.
- Content centered horizontally and vertically (`max-w-xl`), with no card, border, background or gradient:
  - Heading, exactly: `Create a project or open an existing one`. It uses the H2 type scale from `ui-context.md` (38px, weight 600, from the `md` breakpoint, smaller on narrow screens).
  - Description, exactly: `Start a new architecture workspace, or choose a project from the sidebar.` Muted text (`text-copy-muted`).
  - A `New Project` button (default variant) with the `Plus` icon before the label. Clicking it opens the Create dialog.
- No other content.

## Dialogs: `components/editor/project-dialogs.tsx`

All three use `EditorDialog` and are controlled by the hook. Buttons: `Cancel` uses the outline variant, and the confirm button uses the variant named below.

Name rules (Create and Rename): trimmed, required, 1 to 60 characters (`maxLength={60}` on the input). Duplicate names are allowed. The confirm button is disabled while the trimmed name is empty. If the user has typed and then emptied the field, show an inline `Name is required` message in `text-error`. Do not show it before the field has been touched.

Form behavior: each name dialog wraps its input in a real `<form>` with an `id`. The confirm button sits in the footer and is linked to the form with the `form` attribute. Enter submits through the form's `onSubmit`, not through a key handler. The input has an associated `<label>` (use a native label; the shadcn Label component is not installed and must not be added).

### Create Project

- Title: `Create project`. Description: `Give your architecture workspace a name.`
- Input: label `Project name`, placeholder `e.g. Ride-sharing backend`, auto-focused.
- No ID, URL or slug preview. The project's ID is created by the database after the name is submitted.
- Confirm: `Create` (default variant). While submitting: `Creating…`.

### Rename Project

- Title: `Rename project`. Description: `Current name: "<name>"` (the project's current name).
- Input: label `Project name`, prefilled with the current name, auto-focused with its text selected.
- Confirm: `Rename` (default variant), disabled while the trimmed name is empty **or** unchanged from the current name. While submitting: `Renaming…`.

### Delete Project

- Title: `Delete project?`. Description: `"<name>" will be permanently deleted. This can't be undone.`
- No input, no form, no typing confirmation.
- Confirm: `Delete` (destructive variant, shadcn's own styling). While submitting: `Deleting…`.
- Initial focus must not land on the destructive button.

### Shared dialog behavior

- Dismissing (Escape, overlay click, close button, Cancel) closes the dialog and discards form state. Reopening starts fresh.
- While loading: the input and both buttons are disabled, and the dialog cannot be dismissed.
- Loading is simulated: the submit awaits a short placeholder delay (about 400 ms) before applying the in-memory change and closing. Keep this in one clearly commented place so a later unit can replace it with a real API call. Do not add retry or failure UI. There is no failure path yet.

## Hook: `hooks/use-project-dialogs.ts`

A `"use client"` hook that manages UI state only. It receives the data operations as parameters, so it can be wired to a real API later without changing its shape:

- Input: `{ onCreate(name), onRename(id, name), onDelete(id) }` (each may return a promise).
- State: which dialog is open (`create`, `rename`, `delete`, or none); the target project (for rename and delete); the name field value; whether the field has been touched; the loading flag.
- Exposes: `openCreate()`, `openRename(project)`, `openDelete(project)`, `close()`, the field value and its setter, derived validity flags, `submit()`, and the loading flag.
- It must not own the project list, and it must not call any API.

## Sidebar changes: `components/editor/project-sidebar.tsx`

The only allowed changes to the sidebar (replacing spec 02's "no backdrop" rule below `md`, see next section):

1. New props: `projects: ProjectListItem[]`, `onCreate: () => void`, `onRename: (project) => void`, `onDelete: (project) => void`.
2. `My Projects` tab lists the items with `isOwner: true`. `Shared` tab lists the items with `isOwner: false`. If a tab's list is empty, keep the existing empty state.
3. Each row shows the project name on one line, truncated with an ellipsis (the name is available to assistive tech in full). Owned rows also show two ghost icon buttons: Rename (`Pencil`) and Delete (`Trash2`), with `aria-label`s that include the project name (for example `Rename Chat service`). They are always visible (no hover-only reveal), so they work on touch and keyboard. **Shared rows render no actions at all**, not disabled ones.
4. Rows are not clickable.
5. The footer `New Project` button calls `onCreate` (opens the Create dialog). Opening a dialog does not close the sidebar.
6. Keep everything else from spec 02: floating `fixed` overlay, no layout shift, slide animation, `inert` when closed, Escape closes, tab behavior.

## Mobile scrim

"Mobile" means below Tailwind's `md` breakpoint (768px).

- Below `md`, while the sidebar is open, a full-screen scrim sits behind the sidebar and above the page content. Tapping or clicking it calls `onClose`.
- The scrim stacks below the navbar and sidebar (their `z-40`) and above the page content, so the navbar toggle still works. Use one z-index value (`z-30`). Do not invent a z-index scale.
- At `md` and above there is no scrim and nothing changes from spec 02.
- The scrim is rendered by `ProjectSidebar`, is hidden from assistive tech (`aria-hidden`), and is not focusable.
- Color: add one new token, `--scrim`, to `globals.css`: dark `rgba(0, 0, 0, 0.6)`, light `rgba(30, 33, 36, 0.4)` (the ink color at 40%), mapped in `@theme inline` as a `bg-scrim` utility. No other token is added or changed. Update the Effects section of `ui-context.md` with the new token.
- Spec 02 said the sidebar has no backdrop and is not modal. That remains true at `md` and above. Update the "Layout Patterns" text in `ui-context.md` to say a scrim is used on small screens only.

## Hard rules

- Tokens only. No hex values, no raw palette classes (`zinc-*`, `gray-*`, `purple-*`, `black`) and no `dark:` variants for colors in anything we write. The single permitted new value is `--scrim` in `globals.css`.
- Radii follow the scale (`rounded-md` for panels and buttons, `rounded-sm` / `rounded-xs` for small elements). Weights are 400 / 500 / 600 only.
- No gradients, glows, cards on the home screen, or tinted icon tiles.
- Icons are `lucide-react`, stroke-based only. Sizes per `ui-context.md`.
- Add `"use client"` only where hooks or browser APIs are needed. Report which files got it.
- Do not modify `components/ui/*`. Do not install new packages.
- Scratch or test files used for verification are deleted before reporting done.
- Add `hooks/` and `types/` to the "File Organization" list in `code-standards.md`. Do not commit or push.
